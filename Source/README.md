# ISO Assemble 1.4.5 source

Swift/AppKit desktop application with a local Python engine. Version 1.4 added **Camera files with shared audio** alongside the existing Resolve and Premiere multicam-project modes. Version 1.4.1 added an explicit first output choice, verified MP4-reference-to-MOV relinking, exact WAV-to-camera-part mapping and an opt-in Resolve Mix review mode. Version 1.4.2 replaced the exact Resolve version whitelist with minimum-version checks and a native compatibility proof on the installed editor. Version 1.4.3 added fresh Resolve projects for each Create, organized media bins, active edit verification, exact-export hash checks, and optional Accessibility-assisted viewer preparation. Version 1.4.4 embeds the selected primary audio in the initial Resolve FCPXML import and verifies the resulting A1 track before export and after reimport. Version **1.4.5 (build 10)** fits the entire edit before attempting the optional Multicam controls and improves the explicit Accessibility-permission workflow. Read the included user instructions and validation report for the actual test coverage and editor restrictions.

## Rebuild

Requires Apple's command-line build tools and make. Runtime source archives are distributed inside the app under `Contents/Resources/Legal`.

1. Copy `Python-3.11.16.tar.xz`, `ffmpeg-8.1.3.tar.xz`, and the current `build-runtimes.sh` into a build/vendor folder.
2. Run `bash build-runtimes.sh /absolute/build/vendor`. This creates `python-runtime` and `ffmpeg-runtime` in that vendor folder. To rebuild only FFmpeg/ffprobe, append `--ffmpeg-only`. The minimal LGPL media runtime is built with network support disabled. The new camera-file mode requires FFmpeg in addition to ffprobe; an older probe-only runtime is insufficient. No OpenSSL, Homebrew, pip or third-party Python modules are required at runtime.
3. Run `VENDOR_DIR=/absolute/build/vendor bash build.sh /absolute/output/ISO\ Assemble.app`. The packager relocates Mach-O dependencies, rejects unbundled non-system libraries, includes complete source/license archives and ad-hoc signs the app. Use a fresh output app when changing runtime capabilities so an older bundled runtime is not reused.
4. Run the bundled Python in `engine` with `-B -m unittest discover -v`. The repository form is `python3 -B -m unittest discover -s Source/engine -v`. Four generated-media integration tests are opt-in: set `ATTACH_AUDIO_TEST_FFMPEG=/absolute/path/to/full/ffmpeg` when running the suite. That developer FFmpeg needs fixture-generation encoders and filters intentionally omitted from the app; it is not required to use ISO Assemble.
5. For distribution, use `sign-and-notarize.sh APP 'Developer ID Application: ...' KEYCHAIN_PROFILE`, then `package-dmg.sh APP OUTPUT_DMG README`. This final signing path is supplied but has not been validated with a Developer ID identity and notarytool credentials.

## Shared-audio camera files

This path discovers numbered camera MP4 or MOV parts and the selected source's numbered WAVs directly under an ATEM recording root. It must remain independent of DRP parsing, Resolve scripting and Premiere. Media processing uses the bundled FFmpeg locally; source files are never changed.

The mapping uses exact rational frame/sample arithmetic and selected WAV lengths. Do not align using BWF `time_reference`, assume matching WAV/video suffixes, round fractional sample boundaries, pad or trim mismatches, sum original camera audio, or guess missing timing. Verify each camera's part set, frame count, frame rate, presentation timing and timecode before reusing a shared mapping. Keep the source video's timing and write a proper output timecode track; a fixed 30000 track timescale is appropriate only for the corresponding source time base.

The implementation uses FFmpeg's documented [sample-based atrim filter](https://ffmpeg.org/ffmpeg-filters.html#atrim) and [MOV muxer options](https://ffmpeg.org/ffmpeg-formats.html#mov_002c-mp4_002c-ismv). Call FFmpeg with an argument list so filenames and filter parameters are not interpreted by a shell.

The accepted source video is progressive H.264 at a supported constant rate; the original raster is preserved. Source WAVs must be signed 24-bit PCM, 48 kHz and stereo. Each output contains stream-copied video and one selected audio stream encoded as 24-bit PCM. Output verification must compare compressed video payload, exact decoded PCM sample content and count, frame count and timecode with the mapped source ranges. These checks detect transfer or mapping errors; they do not establish whether a WAV contains the intended microphone or mix.

See [SharedAudio](../Documentation/SharedAudio.md) for the user contract. The local bridge exposes `audio-scan --root ROOT --output OUT`, `audio-plan --root ROOT --audio 'CAM 8' --output OUT`, and `audio-build --output OUT`. Put both bundled `runtime/ffprobe/bin` and `runtime/ffmpeg/bin` on PATH. Outputs and owned job state live in `OUT/Attached Audio`; matching completed outputs can be verified and reused on a safe resume, while changed inputs or conflicting files are refused.

## Multicam project conversion

`premiere.py` writes supported legacy XMEML, imported by Premiere as native multiclips. `verify_premiere.py` only reads Premiere's saved native project to verify exact timing and angles; it never modifies the project. Resolve uses the documented local scripting API plus native FCPXML import. No Resolve database is modified.

`audio_timeline.add_primary_audio` embeds the verified primary-audio selection into the generated multicam FCPXML before Resolve imports the edit. This replaces the normal 1.4.3 flow of importing video first and appending independent audio afterward. Each selected physical audio file appears once, with its full verified range on one independent stereo A1 track. Camera multicam audio remains disabled, source media stays unchanged, and real gaps between recording sessions remain silent. Exact-length WAV mapping can use one WAV across multiple video parts; a long WAV must not restart at a video rollover or be shifted by contradictory BWF metadata. Program recordings use their verified media timecode as the asset origin while source offsets remain zero.

Keep the WAV's **source clock** separate from its **timeline placement**. Resolve can treat a WAV as offline when FCPXML declares source time zero despite a nonzero BWF `time_reference`. The source-clock helper expresses that sample clock as its floored frame at the exact project rate, modulo one day, on both the asset and audio component. This addresses source offset zero; it does not shift the timeline to the BWF timestamp. The independent exact-length mapping still determines when the file plays. Resolve's displayed Start TC may round differently, so do not substitute that display value or change the verified edit positions to make the clocks agree.

`audio_validation.verify_primary_audio` requires the selected physical file paths, exact timeline start/end frames, source offsets and complete recording-session coverage. An empty A1, duplicate/missing clips, extra audio tracks or incorrect sources fail the conversion. Where Resolve exposes them, checks also require enabled track/clips and unmuted stereo source channels 1 and 2. The report records which optional API checks ran. Do not specify FCPXML `srcCh="1,2"` for this route: the local Resolve import mapped that explicit value incorrectly; the verified default stereo mapping is used instead. These structural and channel checks do not measure source loudness or the user's monitoring device.

The full creation route checks the imported audio before export and validates it again in the exact reimported DRP. Keep `audio_assembly` and `audio_embedded` in the conversion manifest, `audio_import_validation` with the creation evidence, and `primary_audio_validation` in the final validation report. Never report success based solely on audio assets being present in the media pool. The initial FCPXML import contains both the native multicam video edit and its chosen primary mix; the separate small compatibility proof remains focused on editor capabilities.

The normal Resolve Create flow allocates a new directory under `RESULTS/Projects/<dated run folder>` with a random suffix and chooses an available Resolve project name. It does not consume legacy conversion state, old exports or a previous run's compatibility cache as its result. Do not turn this into a resume operation when the user rescans and presses Create. Older projects and source files must remain untouched. The lower-level apply/layout ownership checks are still idempotent within a single run for engineering safety; that is separate from the desktop app's always-fresh contract. After successful full export verification, only this run's temporary compatibility/reimport projects with matching saved IDs are eligible for cleanup. Preserve mismatches and report cleanup warnings; restore the finished project by identity.

`resolve_compatibility.py` gates cut-only creation at Studio 21 or later and Mix review at Studio 21.1 or later. Before the full conversion, it must prove native multicam import, two camera selections, save/export/reimport, and optional transition geometry on the installed Resolve. It needs two different camera clips with at least 12 overlapping frames. These API checks do not claim a UI angle-switch exercise.

For each new run, proof artifacts live in its own `OUT/Resolve Compatibility`: `state.json`, `Compatibility Report.json`, `Proof.fcpxml` and `Proof.drp`. The two project names use a saved owner token: `ISOAssemble_Compat_<token>` and its `_Reopen` partner. Existing project IDs must match saved ownership before replacement. An already named current project is saved and restored by name and ID; restoration failure prevents a successful report or production conversion. The empty unsaved startup placeholder is handled without a Save As modal. An unsaved project containing work is preserved and must be saved by the user before retrying.

The low-level compatibility helper can validate a cache only when Resolve numeric/display version, exact rate and DF mode, Mix requirement, source paths/sizes/modification times/timing, and proof-module hash match. Normal app Create supplies a fresh run directory, so a previous run's proof is not reused. Never reuse an unrelated project or trust a matching version string as evidence that the proof passed. Compatibility results are separate from full-project validation. Do not turn unit acceptance of a newer version string into a claim that that Resolve release was exercised locally.

`project_layout.py` uses documented `MediaPool.AddSubFolder`, `MoveClips`, `SetCurrentFolder`, timeline identity and playhead APIs. Organization moves only manifest-matched paths and generated multicam/timeline items. It creates numbered Edit, Multicam, Camera Originals, Audio ISOs and Program Reference bins; camera originals have a sub-bin per angle. Unknown user clips stay in place. Keep `organize_project` idempotent, and use read-only `inspect_project_layout` for reopen checks.

`select_edit_session` requires the generated edit identity, opens the Edit page, and verifies the native multicam camera selection at the first actual cut. It skips initial black and recording gaps using exact integer timing. Read-only `inspect_edit_session` always requires the edit to be current; its optional `require_first_cut` also checks the playhead and native item. Do not depend on selected-bin state surviving DRP import.

Full-export validation must identify the exact DRP with SHA-256, recorded in `validation.json`, and must not reuse a verification project for changed export bytes. This check is separate from the small compatibility proof.

Resolve may automatically span consecutive program-reference files. Accept that only after verifying the complete contiguous preflight source set, its start timecode and the exact combined frame count; record the accepted grouping under `program_spans` in `conversion.json`. This handling is for the preserved reference timeline. The selected primary mix still has the exact A1 file inventory and ranges required by `audio_assembly`.

Viewer preparation writes its separate result to `Viewer Setup.json`. Version 1.4.5 attempts it after every successful Create and when the user returns after granting Accessibility through **Enable Automatic View**. **Show Entire Edit** retries for the app's most recently created project. It does not attach to an arbitrary existing project. Permission is requested only from the explicit user action, never automatically during creation. Permission denial retains the verified DRP and manual Shift-Z instructions.

The helper first sets **Full Extent Zoom** through its recognized control, reading back its state. This is the only required fit control. Only afterward does it attempt optional viewer preparation: select the Timeline source viewer, close Inspector, show Media Pool, enable Multicam and select video-only switching. A missing Timeline source selector must not block the fit. Preserve a successful timeline-fit result if an optional control is absent or fails. Read the current fit state before clicking; do not blindly send the toggle shortcut on repeated runs. Stop on lost focus or a mismatched project. This view-only operation must not alter clips, recording gaps, source media or audio. Never count a control-state check as a UI angle-switch or cross-machine viewer-persistence test.
